## API documentation

- `openapi.yaml` (repo root) is the OpenAPI 3.0 contract of record for every HTTP endpoint this app serves, and `postman_collection.json` (repo root) is its Postman Collection v2.1 companion: one request per spec operation, folders matching the spec's tags, collection variable `{{baseUrl}}` defaulting to `http://100.125.239.56:3016`.
- Any change that adds, removes or alters an endpoint — path, method, parameters, request body, response shape, status codes, or auth — must update `openapi.yaml` and `postman_collection.json` in the SAME change. A routes change without the spec and collection updated is an incomplete change. This covers the JSON APIs in `src/lib/api.ts`, the file-based page routes under `src/routes/`, and any new server function or proxy route.
- The app currently serves no auth on any endpoint (local-only household app). If auth is ever added in code, model it as OpenAPI security schemes in the spec and collection-level/folder-level auth in the collection in that same change; never document auth the code does not enforce, and never document an endpoint that does not exist.
- Examples in both files use obviously synthetic values only (fictional merchants, round placeholder amounts) — no real transactions, balances, account identifiers, tokens or personal data. Per-currency amounts in examples stay per-currency; totals are never summed across currencies.
- Validate before committing (all three must pass):
  - Spec: `python3 -m openapi_spec_validator openapi.yaml` (expects `openapi.yaml: OK`; install with `pip install openapi-spec-validator pyyaml`).
  - Coverage diff + collection: `python3 scripts/check-api-docs.py` — re-derives the route inventory from `src/lib/api.ts` and `src/routes/`, diffs it against the spec in both directions (must be zero), validates the spec, and checks the collection is v2.1 and matches the spec's paths and methods one for one.
  - Collection JSON sanity: `python3 -m json.tool postman_collection.json > /dev/null`.
- The `api-docs` local hook in `.pre-commit-config.yaml` runs `scripts/check-api-docs.py` on every commit that touches `openapi.yaml`, `postman_collection.json`, `src/lib/api.ts`, `src/lib/snapshot.ts`, or `src/routes/`, so a stale spec fails at commit time. It needs `python3` with PyYAML (and `openapi-spec-validator` for the spec verdict); where Python is unavailable, run the three commands above manually — that manual gate is required, not optional.
- The snapshot server function `getSnapshot` (`src/lib/snapshot.ts`) has a build-generated RPC URL, not a stable path; it is inventoried in the spec's `info.description` rather than as a path. If it (or any endpoint) ever gains a stable path, add it to the spec and collection in the same change.
- If a generator is later introduced to produce the spec (or the collection) from code, update this section in the same change to name the generator command instead of the hand-editing steps; the coverage gate above stays.
